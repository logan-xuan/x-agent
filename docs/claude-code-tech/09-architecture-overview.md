## 三、AbortController 层级

```
+------------------------------------------------------------------+
|                   AbortController Hierarchy                       |
+------------------------------------------------------------------+
|                                                                   |
|                    +-------------------+                          |
|                    | Parent Controller |                          |
|                    +-------------------+                          |
|                            |                                      |
|              +-------------+-------------+                        |
|              |             |             |                        |
|              v             v             v                        |
|     +------------+  +------------+  +------------+                |
|     |   Child    |  |   Child    |  |   Child    |                |
|     | Controller |  | Controller |  | Controller |                |
|     +------------+  +------------+  +------------+                |
|                                                                   |
|  特性:                                                            |
|  - 父级 abort -> 所有子级自动 abort                               |
|  - 子级 abort -> 不影响父级和兄弟                                 |
|  - WeakRef 防止内存泄漏                                           |
|                                                                   |
|  例外:                                                            |
|  - In-Process Teammate 使用独立 controller (不链接到 leader)      |
|                                                                   |
+------------------------------------------------------------------+
```

## 六、设计原则总结

1. **状态不可变**: AppState 更新使用不可变模式
2. **幂等操作**: 状态转换函数可安全重复调用
3. **资源及时清理**: 终止时清除运行时引用
4. **用户体验优先**: 宽限期允许查看已完成任务
5. **内存控制**: 消息上限和回收机制防止膨胀
6. **故障隔离**: AbortController 层级实现级联取消
7. **灵活通信**: 多层消息路由支持多种场景
8. **上下文隔离**: AsyncLocalStorage 实现进程内隔离

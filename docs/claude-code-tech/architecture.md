# Claude Code 架构分析

## 一、整体架构概览

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                              Claude Code CLI                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────┐ │
│  │   main.tsx  │→ │   REPL.tsx  │→ │ QueryEngine │→ │   Anthropic API     │ │
│  │  (入口点)    │  │  (主界面)    │  │  (LLM引擎)   │  │   (Claude模型)       │ │
│  └─────────────┘  └─────────────┘  └─────────────┘  └─────────────────────┘ │
│         ↓               ↓               ↓                                    │
│  ┌─────────────────────────────────────────────────────────────────────────┐│
│  │                         Tool System (工具系统)                           ││
│  │  BashTool | FileReadTool | FileWriteTool | GrepTool | AgentTool | ...   ││
│  └─────────────────────────────────────────────────────────────────────────┘│
│         ↓               ↓               ↓                                    │
│  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐ ┌────────────────────┐  │
│  │ Permission   │ │   Command    │ │   Service    │ │      Bridge        │  │
│  │   System     │ │   System     │ │    Layer     │ │      System        │  │
│  └──────────────┘ └──────────────┘ └──────────────┘ └────────────────────┘  │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 二、核心设计哲学

1. **工具优先 (Tool-First)**: 所有 AI 能力都通过标准化的 Tool 接口暴露
2. **权限隔离 (Permission Isolation)**: 每个工具调用都经过权限检查
3. **流式处理 (Streaming)**: LLM 响应和工具执行都支持流式输出
4. **懒加载 (Lazy Loading)**: 重型模块延迟加载，优化启动时间
5. **可扩展性 (Extensibility)**: 通过 Plugin/Skill/MCP 三层扩展机制

## 三、核心模块详解

### 1. 入口与启动流程 (`main.tsx`)

```
启动流程:
┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  Prefetch    │ →  │  Migrations  │ →  │  Commander   │ →  │  Ink/React   │
│  (并行预取)   │    │  (配置迁移)   │    │  (CLI解析)   │    │  (UI渲染)    │
└──────────────┘    └──────────────┘    └──────────────┘    └──────────────┘
      ↓
┌─────────────────────────────────────┐
│ 并行预取:                            │
│ - MDM Settings (企业配置)            │
│ - Keychain Prefetch (密钥预取)       │
│ - API Preconnect (API预连接)         │
│ - GrowthBook Init (特性开关)         │
└─────────────────────────────────────┘
```

**核心设计**: 通过并行预取优化冷启动时间，将 I/O 密集操作前置。

### 2. 查询引擎 (`QueryEngine.ts`)

```
QueryEngine 调用链:
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│ submitMessage│ →  │  API Call   │ →  │  Stream     │ →  │  Tool Loop  │
│  (提交消息)  │    │  (调用API)   │    │  (流式响应)  │    │  (工具循环)  │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
                                                               ↓
                                            ┌─────────────────────────────┐
                                            │ 工具执行 → 结果返回 → 继续对话 │
                                            └─────────────────────────────┘
```

**核心职责**:
- 管理与 Claude API 的通信
- 处理流式响应
- 执行工具调用循环
- Token 计数与成本追踪
- 重试逻辑与错误处理

### 3. 工具系统 (`src/tools/`)

```
Tool 接口定义:
┌─────────────────────────────────────────────────────────────────┐
│  Tool<Input, Output>                                            │
├─────────────────────────────────────────────────────────────────┤
│  - name: string                    // 工具名称                   │
│  - inputSchema: ZodSchema          // 输入验证 (Zod)             │
│  - call(input, context)            // 执行逻辑                   │
│  - checkPermissions(input)         // 权限检查                   │
│  - isReadOnly(input)               // 是否只读                   │
│  - isConcurrencySafe(input)        // 是否可并发                 │
│  - prompt()                        // 系统提示词                 │
│  - renderToolUseMessage()          // UI 渲染                   │
└─────────────────────────────────────────────────────────────────┘
```

**工具执行编排** (`toolOrchestration.ts`):
```
工具并发策略:
┌─────────────────────────────────────────────────────────────────┐
│  partitionToolCalls()                                           │
│  ├── 只读工具 (isConcurrencySafe=true)  → 并发执行 (max=10)      │
│  └── 写入工具 (isConcurrencySafe=false) → 串行执行              │
└─────────────────────────────────────────────────────────────────┘
```

### 4. 权限系统 (`src/utils/permissions/`)

```
权限检查流程:
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│ Tool Call   │ →  │ Rule Match  │ →  │ Mode Check  │ →  │ User Prompt │
│ (工具调用)   │    │ (规则匹配)   │    │ (模式检查)   │    │ (用户确认)   │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘

权限模式:
┌─────────────────────────────────────────────────────────────────┐
│  default        - 每次询问用户                                   │
│  plan           - 计划模式，只读操作自动允许                      │

└─────────────────────────────────────────────────────────────────┘
```

## 四、关键调用链路

### 1. 用户输入 → LLM 响应 → 工具执行

```
User Input
    ↓
PromptInput.tsx (输入组件)
    ↓
handlePromptSubmit() (提交处理)
    ↓
QueryEngine.submitMessage() (提交到引擎)
    ↓
Anthropic API (流式调用)
    ↓
Stream Response (流式响应)
    ↓
Tool Use Block? ─── Yes ──→ toolOrchestration.runTools()
    │                              ↓
    │                       checkPermissions()
    │                              ↓
    │                       tool.call() (执行工具)
    │                              ↓
    │                       Tool Result (工具结果)
    │                              ↓
    No                      Continue Loop (继续循环)
    ↓
Text Response (文本响应)
    ↓
Render to UI (渲染到界面)
```

### 2. 权限检查流程

```
Tool Invocation
    ↓
hasPermissionsToUseTool()
    ↓
┌─────────────────────────────────────┐
│ 1. Check Deny Rules (拒绝规则)       │
│ 2. Check Allow Rules (允许规则)      │
│ 3. Check Ask Rules (询问规则)        │
│ 4. Check Permission Mode (权限模式)  │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│ auto mode?                          │
│   → bashClassifier / yoloClassifier │
│ plan mode?                          │
│   → isReadOnly() check              │
│ default mode?                       │
│   → User Prompt                     │
└─────────────────────────────────────┘
    ↓
Permission Result (allow/deny/ask)
```

### 3. MCP 工具调用

```
MCPTool.call()
    ↓
findMcpServerConnection() (查找连接)
    ↓
callMCPTool() (调用 MCP 工具)
    ↓
┌─────────────────────────────────────┐
│ 1. Validate Input (验证输入)         │
│ 2. Check Timeout (超时检查)          │
│ 3. Handle Auth (处理认证)            │
│ 4. Transform Result (转换结果)       │
└─────────────────────────────────────┘
    ↓
processMCPResult() (处理结果)
    ↓
Return to QueryEngine
```

## 五、技术栈总结

| 层级 | 技术选型 | 用途 |
|------|---------|------|
| 运行时 | Bun | 高性能 JS/TS 运行时 |
| 语言 | TypeScript (strict) | 类型安全 |
| UI 框架 | React + Ink | 终端 UI |
| CLI 解析 | Commander.js | 命令行参数 |
| Schema | Zod v4 | 运行时验证 |
| 搜索 | ripgrep | 代码搜索 |
| 协议 | MCP SDK, LSP | 扩展协议 |
| API | Anthropic SDK | LLM 调用 |
| 遥测 | OpenTelemetry | 可观测性 |
| 特性开关 | GrowthBook | A/B 测试 |
| 认证 | OAuth 2.0, JWT | 身份验证 |

## 六、设计亮点

1. **并行预取**: 启动时并行加载配置、密钥、API 预连接
2. **工具并发**: 只读工具并发执行，写入工具串行执行
3. **流式架构**: 全链路流式处理，响应即时
4. **权限分层**: 规则 → 模式 → 分类器 → 用户确认
5. **死代码消除**: `feature()` 宏实现编译时特性开关
6. **扩展三层**: Plugin (插件) / Skill (技能) / MCP (协议)

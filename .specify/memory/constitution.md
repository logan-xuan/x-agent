# x-agent2 项目宪法

## 核心原则

### I. 模块化架构优先
每个功能都应作为模块化组件开始；组件必须自成一体、可独立测试、有文档说明；
遵循低耦合高内聚原则，同时确保每个模块可集成，不可重复造轮子，代码高复用率，代码或文件注释明确，变更需求时需要全面评估上下游的依赖和服务提供的影响面。这确保了AI助手系统的可扩展和可维护架构。

### II. 多层架构接口
每一层系统都要通过标准化接口暴露功能；分层通信协议：表达层 → 网关层 → 代理核心 → 工具/插件/记忆 → 数据库管理层；在保持关注点分离以保证可维护性的同时，支持跨层通信。

### III. AI代理为中心的开发（强制执行）
AI代理开发必须遵循TDD原则：编写规格说明 → 用户批准 → 实施遵循规划 → 然后开发；在AI环境中也必须严格执行红-绿-重构循环以确保质量。

### IV. 集成的记忆和插件系统
需要特别关注的重点领域：记忆系统集成以实现自我感知，插件系统以实现可扩展性，代理-核心协调，跨模块通信模式。

### V. 可观测性和安全性
所有组件都需要结构化日志以确保可调试性；采用安全优先的方法，实施权限控制和安全执行；从简单开始，运用YAGNI（您不需要它）原则同时构建复杂的AI功能。

### VI. 文档语言
规划和设计文档语言仅使用中文输出

## 需求澄清

### 功能需求定义
- **主要功能**: 一个可进化的个人Agent智能体，自然语言聊天、技能扩展、网络搜索、浏览器自动化、CLI命令执行、文件系统访问、定时任务管理
- **质量标准**: 所有模块必须可测试且可维护，可集成测试

### 架构定义
- **表达层**: 用户界面和通信渠道（Web UI、实时日志、设置）
- **网关层**: 会话管理、消息排队、权限控制、通信链路管理
- **代理核心**: LLM推理引擎、上下文管理、任务规划、技能路由、记忆系统、安全守卫
- **工具/插件层**: 系统工具和用户可扩展插件
- **数据库管理层**: 向量数据库、SQLite、缓存和日志

## 模块分解

### 表达层模块
- Web UI（React + TS）带有WebSocket/REST API
- 消息接入扩展渠道

### 网关层模块
- 会话管理和消息队列流控制
- 权限控制和统一日志
- 通信链路管理
- agent心跳检测机制

### Agent核心模块
- LLM推理引擎
- 上下文工程（子代理选择、压缩、外部记忆存储）
- 任务规划器（Loop）
- 技能路由器
- 记忆系统

### 工具/插件层模块
- 系统级工具和插件（模块化、可插拔）
- workspace目录中的用户自定义技能

### 数据库管理层模块
- 向量数据库（sqlite-vss）
- 用于历史记录的SQLite
- 缓存和日志
- 用于用户日志和记忆的Markdown文件存储

## 质量保证
- 所有功能变更需要通过全面测试（单测、集成测试）
- 保持良好的错误处理和用户反馈机制
- 定期进行代码审查和重构

所有变更都必须符合此宪法；修订需要文档、批准，如需要迁移计划。宪法凌驾于所有其他开发实践之上。所有PR/审查必须验证是否符合架构原则。复杂性必须有明确的好处证明。

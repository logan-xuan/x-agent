# 飞书与钉钉渠道适配器扩展计划

## 架构概述

两个适配器均遵循现有 `ChannelAdapter` 抽象基类，采用 **Stream 长连接** 接收消息、**消息更新 API** 实现流式回复。无需公网暴露，适配器在 `start()` 时主动与平台建立长连接。

```
平台服务器
    ↕ Stream/WebSocket 长连接
ChannelAdapter (dingtalk/feishu)
    ↓ to_envelope()
Envelope → GatewayDispatcher → Agent
    ↓ GatewayEvent
render_response() → 平台消息更新 API（流式更新）
```

## 前置依赖

- 钉钉：`dingtalk-stream` SDK（官方 Stream 模式 SDK）
- 飞书：`lark-oapi` SDK（支持 WebSocket 长连接事件订阅）

## Task 2：实现钉钉 Channel Adapter

**目标**：实现 `DingtalkChannelAdapter`，基于 `dingtalk-stream` SDK 建立 Stream 长连接，接收群聊/单聊消息，并通过消息更新 API 实现流式回复。

**创建文件**：`backend/src/channel/adapters/dingtalk.py`

**核心实现**：
- `start()`：使用 `dingtalk-stream` 的 `DingTalkStreamClient` 建立长连接，注册消息回调
- `stop()`：关闭 Stream 连接
- `to_envelope()`：将钉钉消息回调数据转为 Envelope，提取 sender_id、conversation_id、conversation_type (group/single) 等
- `render_response()`：将 GatewayEvent 转为钉钉消息格式
- **流式回复**：收到消息后先发送占位消息，收集 TEXT_CHUNK 事件逐步更新消息内容，MESSAGE_END 时最终更新
- 消息回调中创建 Envelope → 调用 GatewayDispatcher.dispatch() → 收集 events → 流式更新回复

**钉钉 Stream 模式关键点**：
- 使用 App Key + App Secret 认证
- 支持群聊 @机器人 和单聊场景
- 通过 OpenAPI `POST /v1.0/robot/oToMessages/batchSend` 或回复接口发送/更新消息

## Task 3：实现飞书 Channel Adapter

**目标**：实现 `FeishuChannelAdapter`，基于 `lark-oapi` SDK 的 WebSocket 长连接接收事件，并通过消息更新 API 实现流式回复。

**创建文件**：`backend/src/channel/adapters/feishu.py`

**核心实现**：
- `start()`：使用 `lark-oapi` 的 WebSocket Client 建立长连接，订阅 `im.message.receive_v1` 事件
- `stop()`：关闭 WebSocket 连接
- `to_envelope()`：将飞书消息事件转为 Envelope，提取 open_id、chat_id、message_type、chat_type 等
- `render_response()`：将 GatewayEvent 转为飞书消息格式
- **流式回复**：先通过 `POST /im/v1/messages` 发送初始消息，后续通过 `PATCH /im/v1/messages/{message_id}` 更新消息内容
- 消息事件处理中创建 Envelope → 调用 GatewayDispatcher.dispatch() → 收集 events → 流式更新回复

**飞书 SDK 关键点**：
- 使用 App ID + App Secret 认证
- WebSocket 模式无需配置回调 URL
- 支持群聊 @机器人 和单聊

## Task 4：配置集成与启动注册

**目标**：将两个适配器集成到系统启动流程中，支持通过 `x-agent.yaml` 配置启用。

**改动文件**：
- `backend/x-agent.yaml.example` — 添加飞书和钉钉的配置示例
- `backend/src/config/models.py` — 如需扩展 protocol 字段支持 `"stream"` 协议类型
- `backend/src/channel/registry.py` 或启动入口 — 添加根据配置自动实例化和注册适配器的逻辑
- `backend/src/main.py`（或相关启动文件）— 在应用启动时初始化 Channel 适配器并注册到 ChannelRegistry

**配置格式示例**：
```yaml
multi_agent:
  channels:
    - id: dingtalk_channel
      type: dingtalk
      protocol: stream
      enabled: true
      config:
        app_key: "your-dingtalk-app-key"
        app_secret: "your-dingtalk-app-secret"
    
    - id: feishu_channel
      type: feishu
      protocol: stream
      enabled: true
      config:
        app_id: "your-feishu-app-id"
        app_secret: "your-feishu-app-secret"
  
  bindings:
    - agent_id: main-agent
      match:
        channel: dingtalk_channel
        peer:
          kind: group
          id: "*"
    - agent_id: main-agent
      match:
        channel: feishu_channel
        peer:
          kind: group
          id: "*"
```
